This page documents the Thursday volleyball WhatsApp poll and how it fits into the full weekly flow (Friday turnout check is detailed in Friday turnout guide). Scheduling uses Windows Task Scheduler (not WSL, not browser-use). The poll runs the day before Friday games, checks weather for Lake Hiawatha, NJ, and either sends the poll or a weather cancellation message via Microsoft Edge + CDP.

Project folder: WhatsApp_Web_Poll/ under your tasks_automation repo (paths are relative to the .bat files — no hardcoded drive letters).

Overview

🏐 Purpose

Every Thursday during volleyball season, the automation posts a WhatsApp poll asking whether to play volleyball Friday 6:00 PM at Lake Hiawatha Park. If rain or temperature is outside the playable range, it sends a cancellation text instead.

Stack: Windows Python (py -3) + websocket-client + Edge on localhost:9222 (Chrome DevTools Protocol). No Selenium, Playwright, or browser-use.

Thursday schedule policy (gates)

📅 When the scheduled runner actually fires

Task Scheduler triggers hourly on Thursday (8 AM–11 PM), but schedule_gate.py enforces these rules before anything is sent:

Gate Default Notes
Weekday Thursday only Day before Friday game; SCHEDULE_WEEKDAY=3 (Mon=0)
Season May 12 – Oct 30 Same as whatsapp_poll.py volleyball season
Run window 08:00 – 23:00 local Hourly retries until 11 PM if the poll has not succeeded yet
Success tracking Status JSON %LOCALAPPDATA%\tasks_automation\whatsapp_poll_status.json — retries stop after success
Legacy stamp Date file whatsapp_poll_last_run.txt updated on success (same folder)

Weather logic (inside whatsapp_poll.py)

Check Default
Location Lake Hiawatha, NJ (40.881, -74.387) — NWS may label grid as Boonton
Forecast window Tomorrow 4 PM – 8 PM (game time)
Temperature 65 – 92 °F during that window
Rain ≥ 50% PoP or rain/storm keywords → cancel message

Hourly retries & success/failure status

🔁 Retry until success or 11 PM

If a Thursday run fails (WhatsApp slow to load, CDP error, timeout), the gate allows another attempt on the next hourly trigger until either:

  • The poll (or weather cancel message) is sent successfully → status success, no more retries that day
  • Local time passes 23:00 (11 PM) → gate skips until next Thursday

run_status.py writes JSON status files:

FileFields
whatsapp_poll_status.json date, status (success|failed|pending), attempts, last_attempt, detail
Check status: py -3 schedule_gate.py --status or open logs viewer (scripts_batch_files\whatsapp_poll\view_logs.bat).

Friday turnout check (3 PM / 4 PM)

👥 Low turnout cancellation (separate from Thursday poll)

On Friday, a second automation reads the latest volleyball poll in the group chat. If Yes votes < 6 and today's weather is OK (4–8 PM), it sends a low-turnout cancel message. Scheduled at 3:00 PM with a 4:00 PM retry.

One-time setup

🔧 Before the first scheduled Thursday
  1. Close all Chrome and Edge (Task Manager → end chrome.exe / msedge.exe). Port 9222 must be used by Edge for this automation.
  2. Run start_edge_cdp.bat — opens Edge with profile C:\edge-cdp and navigates to https://web.whatsapp.com/.
  3. Scan the QR code with your phone and wait until the chat list loads. This login persists in the Edge CDP profile.
  4. Ensure Python 3 is on PATH (py -3 or python). The scheduled runner auto-installs websocket-client if missing.
Edge vs Chrome on port 9222

If Chrome already owns port 9222, start_edge_cdp.bat reports a warning and the poll may attach to the wrong browser. Fully quit Chrome before starting Edge CDP.

What happens on Thursday

⚙️ End-to-end flow
Task Scheduler (hourly Thu 8–23, or Fri 15:00 / 16:00) │ ▼ run_whatsapp_poll_scheduled.bat OR run_whatsapp_turnout_check_scheduled.bat │ ├─► schedule_gate.py / schedule_gate_turnout.py │ skip? (wrong day / season / time / already succeeded) → exit 0 │ failed earlier today? → allow retry │ ├─► start_edge_cdp.bat → Edge localhost:9222 (C:\edge-cdp) │ 10s warmup + longer WhatsApp load waits when SCHEDULED=1 │ ├─► whatsapp_poll.py │ Thu: weather_check_tomorrow() → poll OR rain/temp cancel │ Fri: weather_check_today() → read poll → low-turnout cancel if Yes < 6 │ └─► --mark-success or --mark-failed → run_status.py JSON
  1. Gate must pass (Thursday in season, 08:00–23:00, not already success today).
  2. Edge CDP must be reachable; script starts Edge if needed.
  3. Thursday: weather checks tomorrow 4–8 PM; rain/temp cancel OR poll.
  4. WhatsApp Web must finish loading chats (up to 300s + 25s settle when scheduled).
  5. On success, status JSON stops further hourly retries that Thursday.

Troubleshooting

Stuck after on: https://web.whatsapp.com/

WhatsApp is not logged in or still loading. Scan QR in the Edge C:\edge-cdp window; wait for chats. Re-run after login.

Port 9222 is in use — may be Chrome

Quit all Chrome instances. Run start_edge_cdp.bat so Edge owns CDP.

Scheduled run does nothing

Check logs/whatsapp_poll_*.log for skip: lines (wrong weekday, outside season, outside 08–23, or already succeeded today). Gate exits 0 on skip — that is normal.

Log stops at [ok] Edge CDP is up. with no [wapoll] lines

Incomplete run — Python step did not finish. Hourly retry should pick it up. Avoid using the mouse in Edge during scheduled runs. See logs guide.

WhatsApp slow to load chats

Scheduled mode waits up to 300s plus a 25s settle after the chat list appears. Keep Edge (C:\edge-cdp) logged in and unlocked.

Machine asleep / locked

Task runs in your interactive session. Unlock Windows after wake; StartWhenAvailable runs missed hourly slots when the PC comes back.

Reset status for testing

Delete %LOCALAPPDATA%\tasks_automation\whatsapp_poll_status.json and whatsapp_poll_last_run.txt to allow another Thursday send the same day.

Environment variables

🔧 Overrides

Schedule gate (schedule_gate.py):

  • SEASON_START_MONTH, SEASON_START_DAY, SEASON_END_MONTH, SEASON_END_DAY
  • SCHEDULE_WEEKDAY — default 3 (Thursday)
  • SCHEDULE_START_HOUR, SCHEDULE_END_HOUR — default 8 and 23
  • WHATSAPP_POLL_STAMP — legacy success date file
  • WHATSAPP_POLL_STATUS — path to status JSON

Turnout gate (schedule_gate_turnout.py):

  • TURNOUT_WEEKDAY — default 4 (Friday)
  • TURNOUT_RUN_HOURS — default 15,16 (3 PM and 4 PM)

Poll / weather / turnout (whatsapp_poll.py):

  • CONTACT, SEND, ACTION (poll, check_turnout, send_low_turnout_cancel)
  • CANCEL_MSG, TEMP_CANCEL_MSG, LOW_TURNOUT_MSG
  • MIN_PLAYERS — default 6 Yes votes required
  • SCHEDULED=1 — longer WhatsApp load timeouts
  • SESSION_TIMEOUT_SEC, POST_READY_SETTLE_SEC, PRE_SEARCH_SETTLE_SEC
  • WEATHER_LAT, WEATHER_LON, TEMP_MIN_F, TEMP_MAX_F
  • SKIP_WEATHER=1 — bypass weather check
