This page documents how the Thursday volleyball WhatsApp poll is scheduled on Windows using Task Scheduler (not WSL, not browser-use, not Hermes). The poll runs the day before Friday games, checks weather for Lake Hiawatha, NJ, and either sends the poll or a cancellation message via Microsoft Edge + CDP.

Project folder: WhatsApp_Web_Poll/ under your tasks_automation repo (paths are relative to the .bat files — no hardcoded drive letters).

Overview

🏐 Purpose

Every Thursday during volleyball season, the automation posts a WhatsApp poll asking whether to play volleyball Friday 6:00 PM at Lake Hiawatha Park. If rain or temperature is outside the playable range, it sends a cancellation text instead.

Stack: Windows Python (py -3) + websocket-client + Edge on localhost:9222 (Chrome DevTools Protocol). No Selenium, Playwright, or browser-use.

Schedule policy (gates)

📅 When the scheduled runner actually fires

Task Scheduler may trigger often (wake, unlock, weekly time), but schedule_gate.py enforces these rules before anything is sent:

Gate Default Notes
Weekday Thursday only Day before Friday game; SCHEDULE_WEEKDAY=3 (Mon=0)
Season May 12 – Oct 30 Same as whatsapp_poll.py volleyball season
Run window 08:00 – 18:00 local Poll asks for Friday noon confirmation — morning/afternoon Thursday is ideal
Once per day Stamp file %LOCALAPPDATA%\tasks_automation\whatsapp_poll_last_run.txt

Weather logic (inside whatsapp_poll.py)

Check Default
Location Lake Hiawatha, NJ (40.881, -74.387) — NWS may label grid as Boonton
Forecast window Tomorrow 4 PM – 8 PM (game time)
Temperature 65 – 92 °F during that window
Rain ≥ 50% PoP or rain/storm keywords → cancel message

One-time setup

🔧 Before the first scheduled Thursday
  1. Close all Chrome and Edge (Task Manager → end chrome.exe / msedge.exe). Port 9222 must be used by Edge for this automation.
  2. Run start_edge_cdp.bat — opens Edge with profile C:\edge-cdp and navigates to https://web.whatsapp.com/.
  3. Scan the QR code with your phone and wait until the chat list loads. This login persists in the Edge CDP profile.
  4. Ensure Python 3 is on PATH (py -3 or python). The scheduled runner auto-installs websocket-client if missing.
Edge vs Chrome on port 9222

If Chrome already owns port 9222, start_edge_cdp.bat reports a warning and the poll may attach to the wrong browser. Fully quit Chrome before starting Edge CDP.

Install the Windows task

⚙️ Task Scheduler triggers
Trigger Behavior
Weekly Thursday 08:00 StartWhenAvailable — if PC was off at 8 AM, runs when it comes on later that Thursday
Resume from sleep System event: Power-Troubleshooter Event ID 1
Session unlock When you unlock Windows (e.g. PC woke Thursday morning)

Double-click install_whatsapp_poll_task.bat in the WhatsApp_Web_Poll folder.

After install: logs appear under WhatsApp_Web_Poll/logs/whatsapp_poll_YYYYMMDD.log.

What happens on Thursday

⚙️ End-to-end flow
Task Scheduler trigger (time / wake / unlock) │ ▼ run_whatsapp_poll_scheduled.bat │ ├─► schedule_gate.py ──► skip? (wrong day / season / time / already ran) → exit 0, log only │ ├─► start_edge_cdp.bat ──► Edge on localhost:9222 (C:\edge-cdp profile) │ ├─► whatsapp_poll.py │ ├─► weather_check_tomorrow() → rain/temp cancel OR send poll │ ├─► ensure_whatsapp_session() → open web.whatsapp.com, wait for chat list │ ├─► search contact "Volleyball Friday" │ └─► send poll OR cancellation message (SEND=1) │ └─► schedule_gate.py --mark (only if exit code 0)
  1. Gate must pass (Thursday, in season, 08:00–18:00, not already sent today).
  2. Edge CDP must be reachable; script starts Edge if needed.
  3. Weather API checks tomorrow 4–8 PM at Lake Hiawatha; cancels on rain or temp outside 65–92 °F.
  4. WhatsApp Web must be logged in in the C:\edge-cdp profile.
  5. On success, stamp file prevents a second send the same day (wake + unlock + 8 AM won't duplicate).

Troubleshooting

Stuck after on: https://web.whatsapp.com/

WhatsApp is not logged in or still loading. Scan QR in the Edge C:\edge-cdp window; wait for chats. Re-run after login.

Port 9222 is in use — may be Chrome

Quit all Chrome instances. Run start_edge_cdp.bat so Edge owns CDP.

Scheduled run does nothing

Check logs/whatsapp_poll_*.log for skip: lines (wrong weekday, outside season, outside 08–18, or already ran). Gate exits 0 on skip — that is normal.

Machine asleep / locked

Task runs in your interactive session. Unlock Windows after wake; the session unlock trigger covers late-morning wake-ups on Thursday.

Reset “already ran today”

Delete %LOCALAPPDATA%\tasks_automation\whatsapp_poll_last_run.txt to allow another send the same day (testing only).

Environment variables

🔧 Overrides

Schedule gate (schedule_gate.py):

  • SEASON_START_MONTH, SEASON_START_DAY, SEASON_END_MONTH, SEASON_END_DAY
  • SCHEDULE_WEEKDAY — default 3 (Thursday)
  • SCHEDULE_START_HOUR, SCHEDULE_END_HOUR — default 8 and 18
  • WHATSAPP_POLL_STAMP — path to once-per-day stamp file

Poll / weather (whatsapp_poll.py):

  • CONTACT, SEND, CANCEL_MSG, TEMP_CANCEL_MSG
  • WEATHER_LAT, WEATHER_LON, TEMP_MIN_F, TEMP_MAX_F
  • SKIP_WEATHER=1 — bypass weather check
